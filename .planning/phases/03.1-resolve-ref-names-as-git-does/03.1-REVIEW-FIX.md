### WR-02: `range_walk` with no tips accepts any hidden id, which git refuses

**Files modified:** `src/git/reads.rs`
**Commit:** 2747101
**Status:** fixed: requires human verification (a state-handling change)
**Applied fix:** `range_walk` now peels `tips` and then `hidden` before the empty-tips
early return. This differs from the review's snippet, which peeled `hidden` first. Peeling
tips first keeps the existing error order: when both lists hold a bad id, the error still
names the tip. The doc now says every id is peeled before any walk. New test:
`git::reads::tests::range_walk_without_tips_refuses_a_missing_hidden_id`. Its oracle is
`git rev-list --not <id>` refusing an id, made in a separate repository, that
`git cat-file -e` confirms is missing. The test requires `Error::Gix` rendering
`peel <hex> to a commit: <gix message>`.
**Evidence:**
- RED, before the fix: `expected Error::Gix, got Ok({}); git refused with fatal: bad object a46c1a97…`.
- GREEN: the new test passed, and so did `range_walk_without_tips_is_empty`. Each was run by name.
- **Not covered:** the test uses a missing id only. A wrong-hash-kind hidden id with no tips
  takes the same `commit_ids` path, but no test exercises it there.

### WR-03: `tree_of`'s accept and refuse paths are untested at the id boundary

**Files modified:** `src/git/reads.rs`
**Commit:** ee389db
**Applied fix:** Five new tests, each using `git diff-tree` as the oracle:
- `tree_diff_from_a_tree_id_matches_git` (`main^{tree}` against `feat`)
- `tree_diff_from_an_annotated_tag_matches_git` (`v1` against `feat`)
- `tree_diff_refuses_a_blob_as_git_does` (renders `tree of <hex>: …`)
- `tree_diff_refuses_a_missing_object_as_git_does` (renders `tree of <hex>: …`)
- `tree_diff_refuses_a_sha1_id_in_a_sha256_repository` (exactly
  `read object id <hex>: a sha1 id in a sha256 repository`)

The two accept tests assert that git's diff is non-empty, so an empty-equals-empty pass is
not possible. A shared `missing_commit` helper replaced the inline setup in the WR-02 test,
in the same file.
**Evidence:** The code under test was unchanged, so all five passed on the first run. To show
they can fail, four mutations of `tree_of` were applied one at a time, each run per test and
then restored with a byte-for-byte `cmp`:

| Mutation of `tree_of` | Tests that failed |
|---|---|
| peel through `commit_id` (commits and tags only) | tree id, blob, missing |
| hex decode without the hash-kind check | sha1-in-sha256 (gix-odb `debug_assert` at `loose/find.rs:12`) |
| `what` renamed from `tree of` to `diff` | blob, missing |
| refuse annotated tags instead of peeling them | tag |

Every mutation was caught, and every new test caught at least one mutation. **Limit:** the
hash-kind mutation is caught by gix-odb's `debug_assert`, which fires only in debug builds.
The test profile is a debug build, so the gate holds; a release build would read the id as
missing instead.

### WR-04: A misspelled `DISCOVERING_SUITES` entry passes silently

**Files modified:** `src/git/testing.rs`
**Commit:** bd4c1f3
**Applied fix:** `discovering_tests_pass_with_a_runner_git_dir` now runs each filter in its
own libtest invocation, and requires exit 0 and at least one passed test for each. The
review's optional check is also added: `discovering_suites_are_the_modules_that_rerun_scrubbed`
asserts that the set of `src/git/*.rs` modules containing `rerun_scrubbed() {` equals
`DISCOVERING_SUITES`. It leaves out `testing.rs`, whose callers are re-executed children.
**Evidence:**
- Before the fix, with `git::refs::tests::` misspelled as `git::refz::tests::`, the old runner
  passed (rc 0). That is the defect.
- After the fix, with the same misspelling, both tests fail. The runner fails on
  `suite git::refz::tests:: … counts (passed, failed) Some((0, 0))`, and the coverage test
  fails on a set mismatch.
- With the `refs` entry dropped from the list, the runner passes and the coverage test fails.
  This control shows why the second test is needed.
- With the real list, both pass when run by name.
- **Not covered:** the scan is not recursive and keys on the literal `rerun_scrubbed() {`. A
  discovering module in a subdirectory of `src/git`, or a call written differently, would not
  be seen.
