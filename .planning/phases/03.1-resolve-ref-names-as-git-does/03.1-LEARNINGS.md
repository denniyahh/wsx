# Phase 03.1 Learnings: Resolve ref names as git does

## Decisions

### Git-layer reads take object ids, never revspec strings
`merge_base`, `ahead_behind`, `range_walk` and `tree_diff` take `git::ObjectId`. Callers supply ids from the repo model or a branch read by exact ref name.

**Rationale:** gix's revspec parser resolves a describe-shaped ref name (`rel-1-g<hex>`) to the commit its hex prefixes, not the ref. Taking ids removes the defect class; reverting to strings re-opens it (rated costly to reverse).
**Source:** 03.1-CONTEXT.md (D-01), 03.1-01-SUMMARY.md, 03.1-03-SUMMARY.md

### `Repo::resolve` / `resolve_commit` removed; one peel via `peel_commit`
An id becomes a commit through `pub fn peel_commit(&ObjectId)` and private `peeled_commit`, with the signatures plan 04-01 already specified, so Phase 4 reuses them. Hex-to-gix conversion is hex decoding only.

**Rationale:** One peel path, shared with Phase 4; no name resolution left anywhere under `src/git/`.
**Source:** 03.1-CONTEXT.md (D-02), 03.1-04-SUMMARY.md

### Ban gix's four public revspec entry points in clippy.toml
`Repository::rev_parse`, `rev_parse_single`, `revision::Spec::from_bstr` and `revision::plumbing::spec::parse` are disallowed, pinned by a test that runs each against a describe-shaped ref.

**Rationale:** A signature alone does not stop a future caller reaching for the parser; the ban makes it a gate failure.
**Source:** 03.1-CONTEXT.md (D-03), 03.1-04-SUMMARY.md

### Ban gix's `mailmap` feature in deny.toml
`[[bans.features]] crate = "gix", deny = ["mailmap"]`, replacing a comment-only exclusion.

**Rationale:** `mailmap` calls `rev_parse_single` inside gix, which the clippy ban cannot see.
**Source:** 03.1-REVIEW-FIX.md (WR-05), 03.1-UAT.md

### Reftable backstop retired (operator decision, 2026-11-03)
`refuse_ref_storage` at discover is the only reftable guard; the backstop inside `Repo::resolve` went with `resolve`, amending Phase 3 CONTEXT.

**Rationale:** On reftable, gix's exact ref read returns `None` and its listing is empty, never an unsupported error, so no backstop is reachable.
**Source:** 03.1-04-SUMMARY.md, STATE.md, 03.1-UAT.md

### User `<branch>` arguments read as exactly `refs/heads/<branch>` (constraint on Phases 4 and 8)
Validated as a branch name, never through git's DWIM ladder or a revspec parser, so a branch named `abc1234` or `rel-1-gdeadbee` reads that branch.

**Rationale:** Same defect class at the CLI boundary; recorded as a forward constraint, not built here.
**Source:** 03.1-CONTEXT.md (D-04), STATE.md

## Lessons

### An id of the other hash kind crashes gix-odb in a test build
Passing a SHA-1 id into a SHA-256 repo hit gix-odb's `debug_assert` (`left: Sha256 right: Sha1`); in a release build it would read as missing. `to_gix` now refuses it before lookup, naming both kinds.

**Context:** Found as the RED of 03.1-02; predicted by RESEARCH Pitfall 1.
**Source:** 03.1-02-SUMMARY.md

### Parity tests that take ids cannot exercise name resolution
After GREEN, the four describe-shaped read tests pinned parity for ids git names; they could no longer fail for the reason their names gave. Review deleted them; the `&ObjectId` signatures, the clippy ban and its pin test are the real guards.

**Context:** Each plan's SUMMARY flagged it; code review raised it as WR-01.
**Source:** 03.1-01-SUMMARY.md, 03.1-03-SUMMARY.md, 03.1-REVIEW-FIX.md (WR-01)

### A suite-list filter that matches nothing passed silently
A misspelled `DISCOVERING_SUITES` entry (`git::refz::tests::`) left the runner-`GIT_DIR` check green. Fix: each filter runs alone and must pass at least one test, plus a test that the list equals the modules calling `rerun_scrubbed() {`.

**Context:** Review finding WR-04; the coverage test scans non-recursively on a literal.
**Source:** 03.1-REVIEW-FIX.md (WR-04)

### A cargo-deny feature-ban control needs a refreshed lockfile
The first attempt to prove the `mailmap` ban failed on version resolution, not the ban, and was discarded as a false control. A valid control needed `cargo update -p gix`, plus a third run with the ban removed showing `deps` OK.

**Context:** Proving WR-05's fix bites.
**Source:** 03.1-REVIEW-FIX.md (WR-05)

### Clippy bans see only direct calls
The ban covers the public entry points in gix 0.90.0 with this crate's features; a gix upgrade or new feature can add another, and a parse gix does internally is invisible. Each gix upgrade must re-check the list; the pin test's lookup-order assertion fails on parser changes.

**Context:** Stated as a scope limit of the ban.
**Source:** 03.1-04-SUMMARY.md

## Patterns

### Oracle-first parity test
Assert git's answer on the ref name first (`git rev-parse --verify`, `git merge-base`, etc.), then wsx's answer on the ids git prints. Test ids never come from gix.

**When to use:** Any git-layer read whose correctness is defined as "what git does".
**Source:** 03.1-03-SUMMARY.md, 03.1-UAT.md

### Refusal test with a git contrast
Pin the whole `err.to_string()` with `assert_eq!`, and assert git's answer for the same input (accepts or refuses) alongside.

**When to use:** Boundary checks that intentionally diverge from git (names at an id boundary) or mirror git's refusals.
**Source:** 03.1-02-SUMMARY.md

### Executor-added mutant controls
Plant a targeted mutant (identity peel, inverted kind check, revspec fallback) in place or in a scratch copy, confirm exactly the expected tests fail, then revert and confirm a clean tree.

**When to use:** After GREEN, when the RED alone does not show which tests would catch a regression.
**Source:** 03.1-01-SUMMARY.md, 03.1-02-SUMMARY.md

### Ban group plus pinned expectation, proven by planted and misspelled controls
Add the paths to `clippy.toml`, pin them with a test calling each under per-call `#[expect(clippy::disallowed_methods)]`, and prove the gate with a planted-call scratch copy and a misspelled-path scratch copy.

**When to use:** Any new disallowed-methods group.
**Source:** 03.1-04-SUMMARY.md

### Count-asserting mechanical rewrite
Convert call sites with exact-match replacements that check each pattern's occurrence count first and abort on a mismatch, then `rg` for leftovers.

**When to use:** Bulk signature migrations of test call sites.
**Source:** 03.1-03-SUMMARY.md

## Surprises

### Two REDs were derived, not measured, until 03.1-03
The ahead/behind (wsx `ahead: 1`) and tree-diff (wsx `b.txt` deleted) defects had come from research; 03.1-03 measured them once each and they matched.

**Impact:** Confirmed the defect spans all four reads, not only `merge_base`.
**Source:** 03.1-03-SUMMARY.md

### Removing `resolve`'s last read callers raised no dead-code warning
The git module's crate-level `expect(dead_code)` covers non-test builds, and test-only callers kept the functions alive in test builds.

**Impact:** Dead code would not have surfaced on its own; 03.1-04 removed callers and functions explicitly.
**Source:** 03.1-03-SUMMARY.md

### `range_walk` with no tips accepted any hidden id
git refuses such a hidden id; wsx returned the empty set without peeling. Now tips and hidden ids are peeled before the empty-tips shortcut.

**Impact:** Review finding WR-02, a state-handling change; only a missing id is tested, not a wrong-kind one.
**Source:** 03.1-REVIEW-FIX.md (WR-02)

### A malformed command left idle shells the agent could not kill
Sourcing `gsd-run-resolver.md` as a script started an interactive `bash`; stopping the three PIDs was denied by the permission classifier.

**Impact:** Leftover processes outlived the plan; no repo effect.
**Source:** 03.1-02-SUMMARY.md
