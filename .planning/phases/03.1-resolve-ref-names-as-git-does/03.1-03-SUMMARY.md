# Phase 03.1 Plan 03: ahead_behind, range_walk and tree_diff on object ids Summary

**All four git-layer reads now take `git::ObjectId`. `range_walk` and `ahead_behind` peel each id to its commit through `commit_id`. `tree_diff` decodes each id with the hash-kind check and peels it to a tree, as `git diff-tree` does. A ref named `refs/remotes/origin/rel-1-g<hex>` now walks, counts and diffs as git does. Before, wsx read it as the commit its hex part prefixes. No read in `src/git/reads.rs` resolves a name any more.**

## Accomplishments

- **Walk.** On the describe-shaped ref with `main` hidden, git walks nothing. On the string API, wsx walked Y. On ids it walks nothing, as git does.
- **Ahead/behind.** git counts `AheadBehind { ahead: 0, behind: 0 }`. On the string API, wsx counted `AheadBehind { ahead: 1, behind: 0 }`. On ids it counts (0, 0), as git does.
- **Tree diff.** git reports no change from the ref to `main`. On the string API, wsx reported `b.txt` deleted, because it diffed Y's tree. On ids it reports no change, as git does.
- **Phase 3 tests.** Every walk, ahead/behind and tree-diff test in `git::reads::tests` passes on ids from `git rev-parse --verify`. Each keeps its git oracle and its control.
- **Error text.** Read errors now name hex ids only: `walk <hex…> --not <hex…>`, `diff <hex> <hex>` and `tree of <hex>`.

- **Replace refs.** The parity claims hold only for repositories without replace refs (RESEARCH Pitfall 9).
- **Concurrency edge.** This is a backstop, not a test. The reads write nothing and keep no state of their own, but parallel use of one `Repo` is not exercised.

## Decisions Made

- `tree_of`'s doc names both of its failure modes. An id of the other hash kind is `ObjectId::to_gix`'s refusal, passed through unchanged. A missing object, or one that does not peel to a tree, is `Error::Gix` with `tree of <hex>`.
- The executor converted the test call sites with a script that does exact-match replacements and checks each pattern's count first. A miscounted pattern aborts the conversion before anything is written. Afterwards an `rg` confirmed that no `range_walk`, `ahead_behind` or `tree_diff` call still takes byte-string literals.
