# Phase 03.1 Plan 04: No name resolution in the git layer, and a gate that refuses one Summary

**`Repo::resolve`, `Repo::resolve_commit` and Phase 3's reftable backstop are deleted. `clippy.toml` now bans gix's four revspec parsers with no production exception, and a pin test calls each one under its own `#[expect]`. That test also records that gix still reads a describe-shaped ref as Y where git reads ONE. Two scratch controls prove the ban both ways: a planted `rev_parse`/`rev_parse_single` call fails `scripts/check.sh clippy`, and so does a misspelled ban path.**

## What this does not establish

- **The ban covers what research read in gix 0.90.0's source.** It covers the public revspec entry points with this crate's features. A later gix release, or a feature such as `mailmap`, can add another. Each gix upgrade commit must re-check the list. The lookup-order assertion fails on any change to gix's parser, which is the intended signal.
- **Clippy sees only direct calls.** It cannot see a parse that gix performs internally on wsx's behalf.
- **Judgement-tier prohibitions.** "No git-layer read turns a name into a commit" and "No silent retirement of a Phase 3 behaviour" are judgement-tier. Their evidence is the ban, both scratch controls and the STATE.md entries.
- **Each control ran once.** A single run shows the gate rejects the planted shape. It does not show that every possible call shape is caught. For example, a call through a trait object or a macro was not tried.
