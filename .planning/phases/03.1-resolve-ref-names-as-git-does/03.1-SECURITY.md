## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| fetched refs -> wsx reads | a collaborator can push a branch named like `describe` output (`rel-1-g<hex>`) or like a hex prefix, which arrives as `refs/remotes/origin/...` | ref names, attacker-chosen |
| caller -> `peel_commit` | an `ObjectId` is a string inside the git module; the boundary refuses anything that is not a full id of this repository's hash kind | object ids |
| read errors -> the user's terminal | an error message prints whatever input it names | hex ids only |
| future code -> gix revspec parsers | a later caller could hand a name to a parser that reads refs after hex prefixes and describe output | ref names |
| gix features -> indirect parser calls | a feature can add an internal parser call that the clippy ban cannot see | build configuration |
| test oracle -> parity claims | a parity test is only as independent as the source of its expected answer | test expectations |
| this phase -> Phase 4 plans | Phase 4's plans were written against code this phase changes | planning artifacts |
