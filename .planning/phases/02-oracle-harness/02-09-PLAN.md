picked it up would record the host's behaviour as the oracle's.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host environment -> harness children | Inherited variables, config files and hooks of the machine running the tests |
| oracle pre-push hook -> git config resolution | The hook unsets the config-location variables before calling git |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-21 | Elevation of privilege | host global or system hooks running in scenarios | high | mitigate | planted-host proof with marker file and wired control |
| T-02-22 | Tampering | inherited `GIT_DIR`/`GIT_WORK_TREE` retargeting a real repository | high | mitigate | decoy repository's refs asserted unchanged under the plant |
| T-02-23 | Elevation of privilege | the oracle hook's `unset GIT_CONFIG_GLOBAL GIT_CONFIG_SYSTEM` re-exposing host config | high | mitigate | global config kept at `$HOME/.gitconfig` and `GIT_CONFIG_NOSYSTEM=1`; tests show the sources unchanged and a control showing the switch when the global file is elsewhere |
| T-02-24 | Information disclosure | SSH agent reachable from tests | medium | mitigate | `SSH_AUTH_SOCK` planted and asserted absent from the built env |
| T-02-SC | Tampering | package installs | high | mitigate | no install in this plan; Cargo.lock unchanged and every cargo call `--locked` |
</threat_model>
