Re-exec contract (testing.rs; later plans use it as is):
- `pub const MARKER: &str = "WSXCHILD ";` A child reports a fact as one line `WSXCHILD <key>=<value>` through `pub fn child_print(key: &str, value: impl Display)`, which prints to stdout.
- `pub fn reexec(child: &str, env: &Env, cwd: &Path, stdin: &[u8]) -> Result<Output, String>`: runs `std::env::current_exe()` with the args `--exact`, `<child>`, `--include-ignored`, `--nocapture`, `env_clear()` then `env`, `current_dir(cwd)`, stdin piped and written with `stdin` then closed, stdout and stderr captured. `child` is the full libtest path, for example `git::spawn::tests::null_stdin_child`.
- `pub fn marker(output: &Output, key: &str) -> Result<String, String>`: the value of the first `WSXCHILD <key>=` line in stdout, else stderr (a hook's stdout reaches git's stderr), or an error quoting both streams lossily.
- A child half is a `#[test]` with `#[ignore = "child half of <parent>; runs only when re-executed"]`; it reads its inputs from the process environment (`std::env::var_os`, reading only) and its working directory.

Decisions this plan implements (03-CONTEXT.md, by heading):
- "Running the git binary": every child gets a null stdin; the helper adds nothing that bypasses hooks or signing, and a caller that needs a bypass passes it explicitly for that call.
- ROADMAP criterion 1: a commit and a merge made through wsx's git layer run the user's own commit hooks and are signed per the user's config.
- "How phase 3 is tested": environment-dependent subjects run in a re-executed child, never through `set_var`.

Shell note: every command in this plan is bash.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| wsx's stdin -> git children | a child reading stdin could block or consume input meant for wsx |
| user's git config (hooks, signing) -> history changes | wsx must not weaken what the user configured |
| test binary -> its re-executed self | a mistyped child name makes a parent pass on zero tests |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-17 | Denial of service | git child waiting on stdin (credential prompt, editor) | medium | mitigate | `Stdio::null()` on every child, proven from a child with a real piped stdin and a control that the data does reach an inheriting process |
| T-03-18 | Elevation of privilege | commits or merges made without the user's hooks or signature | high | mitigate | helper passes argv unchanged; end-to-end proof of `G` signatures and hook runs, with an explicit-bypass control showing `N` and no hooks |
| T-03-19 | Repudiation | re-exec parent passing over a child that never ran | medium | mitigate | parents assert a marker line; `reexec_of_an_unknown_child_has_no_marker` proves a wrong name yields no marker; the child is confirmed in `cargo nextest list` |
| T-03-SC | Tampering | package installs | high | mitigate | no install in this plan; every cargo call is `--locked` |
</threat_model>
