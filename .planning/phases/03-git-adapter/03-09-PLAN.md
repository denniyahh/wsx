Foreign-ownership mechanism (RESEARCH, executed on both targets):
1. `chmod -R go+rX <repo>` first: the host umask is 0077, and without this both tools fail on `Permission denied`, which would prove nothing.
2. The test's own uid is the owner of the freshly made repository directory (`std::os::unix::fs::MetadataExt::uid`), read before any change; no `libc`.
3. uid 0 (the pinned container, GitHub's job container): `chown -R 65534:65534 <repo>`. Otherwise: `/usr/bin/unshare --map-root-user --map-users=auto --map-groups=auto chown -R 1:1 <repo>` (inner uid 1 maps to the first subordinate uid). Use absolute `/usr/bin/unshare`: on this host the user PATH resolves a linuxbrew `unshare` first.
4. Assert the owner changed. Restore with `chown -R <uid>:<gid>` as root, or the same `unshare` with `0:0` otherwise, before the scratch directory is removed; otherwise the host user cannot delete it.
