Criterion 2 with real hooks: started inside a pre-commit hook that git runs for a linked worktree,
wsx resolves that worktree, its common dir and the hook's index; it opens sibling worktrees with
their own git dirs and indexes; a git child it aims at a sibling runs without the hook's
repository variables; and with the removal disabled the same scenario shows the leak. The main
worktree's hook, where `GIT_DIR` is unset and the index path is relative, is covered too.

is the failure the phase exists to prevent: the oracle's N4 defect deleted sibling worktrees'
exclude files from inside a hook.

seven tests with three child halves.
</objective>

Hook test shape (all parents in this plan):
- Build `linked_worktrees`. Install a pre-commit hook in `<main>/.git/hooks` (the common hooks directory, shared by every worktree) with `install_hook`, naming the child half the parent wants.
- Run the commit through `testing::git_in_env` with the scratch's hermetic env plus `WSX_TEST_SIBLING=<wt2>`. Linked case: write a new `b.txt` content in wt1 and run `git commit -m x b.txt` there (a partial commit: git exports a temporary `next-index-<pid>.lock` as `GIT_INDEX_FILE`). Main case: write `a.txt` in main, `git add a.txt`, then `git commit -m y` (staged changes only: git leaves `GIT_DIR` unset and exports the relative `.git/index`).
- The parent asserts the commit exited 0 (a failing child fails the hook and the commit) and then reads the child's facts with `marker`. Paths are compared canonically; an index path is compared as its canonical parent directory joined with its file name, because a lock file may vanish once the commit ends.
- Children print `<unset>` for an absent environment variable.

Decisions this plan implements (03-CONTEXT.md, by heading):
- "Running the git binary": removal applies to any child whose target worktree differs from wsx's own; a child aimed at wsx's own worktree keeps the hook's environment, so a pre-commit's `GIT_INDEX_FILE` still applies; criterion 2's control: with removal disabled, the scenario detects the leak.
- "Opening the repository and refusals": sibling worktrees are reached only through gix's main-repo and worktree-list calls, which switch the environment overrides off.
- "Specific Ideas": inside a hook, wsx behaves as git does for its own worktree and never leaks the hook's `GIT_DIR`/`GIT_INDEX_FILE` into a sibling.

Shell note: every command in this plan is bash.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| git hook environment -> wsx process | git exports `GIT_DIR`/`GIT_INDEX_FILE` scoped to the hooked worktree |
| wsx -> sibling worktrees | anything aimed at a sibling must not inherit the hooked worktree's scope |
