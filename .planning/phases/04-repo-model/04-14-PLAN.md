The read (research P1, F10; spike 001 C1 to C3; probes on git 2.56.1):
- Records are `scope NUL origin NUL key [LF value] NUL`. A key with no `=` prints no LF and reads as one empty value; `key =` prints `key LF`, also one empty value (today's `KeyEmpty` for both). Section and variable are lowercased, a subsection keeps its case (`wsx.sub.sourcebranch` is a three-part key and never matches `wsx.sourcebranch`).
- Origin: `file:.git/config` (relative to the child's cwd) in the main worktree, an absolute path from a linked worktree, `file:config` in a bare repo; an `include.path` file is scope `local` with its own origin; `command line:` for `-c` and `GIT_CONFIG_PARAMETERS` (scope `command`).
- No match: exit 1, empty stdout and empty stderr (measured at planning). A malformed file: exit 128, `fatal: bad config line` (measured at planning). `Git::run` maps a non-zero exit to `GitFailed { argv, status, stderr }` and keeps no stdout, so `read_config` reads `status == Some(1)` with empty `stderr` as no keys.
- `GIT_CONFIG` in the environment makes this child read only that file; that is 04-17's decision, not this plan's.

Test environment: in-process model tests discover the repo in the test process, but wsx's children must see the fixture's hermetic environment, or the host's PATH and global config would choose a different git than the fixture's. `testing::scratch_env_of(path)` finds the ancestor of `path` whose parent is `scratch_root()` (every `Scratch` root is a `TempDir` directly under it) and returns `hermetic_env(root, &root.join("home"))`, equal to that `Scratch`'s `env`.
