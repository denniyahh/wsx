<objective>
Close the one gap phase 4's verification found (CR-01): make the D-22 replacement guard refuse the
replace refs git applies and gix ignores, at any depth under the replace base, so wsx never reads
`.wsx.conf` bytes other than the ones git reads (CONF-07).

Purpose: git keys a replace ref on the last component of its name and reads the id from that
component's first hex digits; gix takes the whole name after the base as the id. A nested ref such
as `refs/replace/team/<blob>`, which a `+refs/replace/*:refs/replace/*` refspec fetches as it is,
therefore changes what git reads and nothing wsx reads, and the guard, which lists only the refs
directly under the base, returns `Ok`. The model then holds a personal-path list from bytes no git
child sees, with no error.
Output: `git::Error::ReplacementRefIgnored`, `git_replace_key`, `Repo::refs_starting_with`, the
any-depth refusal in `refuse_unfollowable_replacements` with a corrected doc comment, seven model
tests and one message test, and a fresh mutation pass and phase gate on the new tip.
</objective>

Measured at planning, git 2.56.1 in a scratch repo, `git cat-file blob <A>` with `A` = `only a`, `B` = `only b`, `C` = `only c`:
- `refs/replace/<A>` -> `B`: `only b` (the control: gix applies this one too).
- Nested, git applies each: `refs/replace/team/<A>`, `refs/replace/x/y/<A>` after `git pack-refs --all`, and `refs/replace/team/<A in uppercase>` all print `only b`.
- Bytes after the id, git applies each: `refs/replace/<A>xyz`, `refs/replace/<A>.bak`, `refs/replace/team/<A>xyz` and `<A>` followed by 24 more hex digits (64 in all) print `only b`.
- git ignores, printing `only a` with `warning: bad replace ref name: ...` on stderr: `refs/replace/team/notes` and `refs/replace/team/<first 39 hex digits of A>`.
- Direct `refs/replace/<A>` -> `B` plus nested `refs/replace/n/<A>` -> `C`: exit 128, `fatal: duplicate replace ref: n/<A>`. Direct `refs/replace/<A>` -> `B` plus nested `refs/replace/n/<B>` -> `C`: `only c`, a two-hop chain.
- gix's side, read from source, not measured: `gix-0.90.0/src/open/repository.rs` about lines 530-550 builds the replacement map from `prefixed(<base>)` with `ObjectId::from_hex(name.strip_prefix(<base>))` and `target.try_id()`, so it skips a symbolic ref and any name whose remainder is not an id, and `gix-hash-0.28.1/src/object_id.rs` line 64 accepts only a 40- or 64-digit buffer. So gix applies a ref exactly when its whole name after the base is an id of the repository's length.

The rule this plan adds, in the equal-base branch only: list the base once at any depth; a ref whose last component git reads an id from, and whose name after the base is not exactly that id, is `ReplacementRefIgnored`. After that step every ref git applies is directly under the base and applied by gix too, so 04-11's duplicate and chain loops over the refs directly under the base see every link either reader follows. The differing-base branch already counts refs at any depth and does not change.
