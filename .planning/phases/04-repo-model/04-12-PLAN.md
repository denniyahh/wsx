component's first hex digits; gix takes the whole name after the base as the id. A nested ref such

child sees, with no error. Separately, `build` peels the integration tip and the workspace tip
before the guard runs, so a chain whose first hop is not a commit fails a peel and is blamed on
`.wsx.conf`.

`git::Error::ReplaceRefsUnreadable`, `git_replace_key`, `is_replace_base`, `Repo::refs_starting_with`,

messages scoped to replace refs in use, thirteen model tests, one unit test and three message tests

The rule this plan adds, in this order inside the guard (`refuse_unfollowable_replacements`, whose checks Task 2 moves into `check_replacements`):
1. Before anything is listed, git's base must be a valid full ref name under `refs/` ending in `/`, other than `refs/` itself and outside git's per-worktree namespaces `refs/worktree/`, `refs/bisect/` and `refs/rewritten/` (`is_replace_base`); otherwise `ReplaceBaseInvalid`. The per-worktree exclusion is read from git-worktree(1), section REFS ("refs inside refs/bisect, refs/worktree and refs/rewritten are not shared"): refs there live in each worktree's own git dir, so with such a base no loose replace ref lies under the common dir, and 04-13's walk of the common dir alone sees every loose ref under any base this accepts.
2. In the equal-base branch only, the base is listed once at any depth. With `hex_len` the repository's id length in hex, `git_replace_key(rest, hex_len)` is the id git reads from a ref whose name after the base is `rest`: the first `hex_len` bytes of `rest`'s last `/`-separated component, lower-cased, when there are that many and all are ASCII hex digits, uppercase included, else `None`. A ref whose key is `Some` and whose `rest` is not exactly `hex_len` bytes long is `ReplacementRefIgnored`. After that step a ref git applies has `rest` equal to its key's length, so it is directly under the base and its whole remainder is an id of the repository's kind, which gix applies too; and every ref gix applies is such a ref. So 04-11's duplicate and chain loops, run unchanged over the refs directly under the base, see every link either reader follows among the refs the listing returns. Entries on disk the listing skips (a symlink, a file whose name is not a valid ref name) and records the packed-refs file holds out of order are 04-13's, which restates this sentence once they are refused.

4.
