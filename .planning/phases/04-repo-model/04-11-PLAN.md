<objective>
Keep the personal-path list on the bytes git reads when replace refs exist: one replacement reads
alike, and a replacement gix and git follow differently is refused before any manifest read.

Purpose: gix follows one replacement hop and ignores a symbolic replacement, while git follows both,
so without a refusal a user-made chain gives a wrong personal-path list with no error.
Output: `git::Error::ReplacementRef`, `ReplacementRefDuplicate`, `ReplaceBaseDiffers`, `git::Error::is_replacement_refusal`, `Repo::refuse_unfollowable_replacements`, its arms in `build` and `require`, the replacement tests.
</objective>

It first settles the base, with the key, the variable and the default as named constants. git's base is `GIT_REPLACE_REF_BASE` from the process environment, read with `std::env::var_os` as `refuse_object_store_env` reads its variables, else `refs/replace/`. gix's base is the string at `gitoxide.objects.replaceRefBase` from `self.repo.config_snapshot()`, where gix maps the same variable, else `refs/replace/`. If either answer holds a ref, the answer is `Error::ReplaceBaseDiffers { value: <gix's base>, git_base: <git's base> }`; if both are empty it returns `Ok(())`, because then neither reader applies a replacement and the checks below have no ref to read.
