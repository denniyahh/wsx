<objective>
Keep the personal-path list on the bytes git reads when replace refs exist: one replacement reads
alike, and a replacement gix and git follow differently is refused before any manifest read.

Purpose: gix follows one replacement hop and ignores a symbolic replacement, while git follows both,
so without a refusal a user-made chain gives a wrong personal-path list with no error.
Output: `git::Error::ReplacementRef`, `Repo::refuse_unfollowable_replacements`, its arms in `build` and `require`, the replacement tests.
</objective>

Fixture recipe:
- Replacement objects, built before `Repo::discover`, because gix loads them at open. `side_manifest(scratch, work, name, bytes)` runs `git switch -q -c <name> workspace/dev`, writes `.wsx.conf`, `commit_all`, `git switch -q -f main`, and returns `git rev-parse <name>`: a real commit, with its tree at `<id>^{tree}` and its blob at `<id>:.wsx.conf`, so nothing needs stdin or `git mktree`. Make the side commits first, because once a cycle exists git cannot read that object. `git replace <a> <b>` links two objects of one kind. A cycle's second link and an uppercase name are `git update-ref refs/replace/<name> <id>`. A symbolic replacement is `git update-ref refs/tags/x <blob id>` then `git symbolic-ref refs/replace/<a> refs/tags/x`, because git refuses a blob under `refs/heads/`. An alternate base is `git update-ref refs/other/<a> <b>`, read in a child with `GIT_REPLACE_REF_BASE=refs/other/` pushed onto `scratch.env.clone()`.
- Missing blob, as in 04-09: `git rev-parse workspace/dev:.wsx.conf`, delete `.git/objects/<first two>/<rest>`, confirm `git cat-file -e <id>` fails.

Measured at planning on gix 0.90.0 and git 2.56.0, reading the blob, the tree and the commit through the plan's read path. The rule in Task 1 is: refuse a ref directly under the replace base that is symbolic, or whose target's hex is itself a replaced object, comparing lower-cased names. Of 25 shapes:
- Disagreement, refused: chain, cycle, self-replacement, symbolic, symbolic with an uppercase name, chain with one or both links uppercase, chain packed, chain under `GIT_REPLACE_REF_BASE=refs/other/`, chain on the tree, chain on the commit, chain on SHA-256.
- Agreement, not refused: none, single, single with an uppercase name, nested name, non-hex name, single with `core.useReplaceRefs=false`, single under the alternate base, chain under `refs/other/` with the variable unset.
- Agreement, refused anyway, which fails safe: a non-hex name pointing at a replaced object, a chain with `core.useReplaceRefs=false`, a chain with `GIT_NO_REPLACE_OBJECTS`, a chain on an unrelated blob.
- Not covered: `GIT_REPLACE_REF_BASE=refs/other` with no trailing slash, where git itself dies with a `BUG` line and gix reads the original.
