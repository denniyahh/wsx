The listing (research P2; spike 001 S2 to S8; probes F6 to F9 on git 2.56.1):
- argv: `--no-lazy-fetch`, `for-each-ref`, `--format=%(refname)%00%(objectname)%00%(symref)`, then each pattern as one argument; cwd `repo.worktree()` or the git dir. No `%(objecttype)`: it makes one ref naming a missing object fail the whole listing (F6). With no pattern `for-each-ref` lists every ref, so `list_refs` with no pattern returns no record and spawns nothing.
- Records end in LF, fields split on NUL; a refname holds neither (git skips bad names, F9).
- Patterns match as globs or as a prefix up to a slash (F8), so the listing is a superset: `refs/remotes/origin/develop` also lists `refs/remotes/origin/develop/x`; `refs/remotes/a*/develop` lists `refs/remotes/ab/develop`.
- No record means absent: a missing ref, a dangling symref (S6, S7), a fifo (S8), a `refs/…`-target symlink (S3), a `main-worktree/` alias (S4), a ref only in a linked worktree's private store (S2), a corrupt or badly named ref (F9), a chain deeper than five refs or a cycle (F7).
- `%(symref)` is the final target of a chain (F7) and `%(objectname)` the final object.

Patterns, from 04-14's `ConfigRead`: configured, `refs/heads/<wsx.sourceBranch>` (already through `is_branch_name`, which refuses `*`, `?` and `[`); not configured, the two `CANDIDATE_PREFIXES`; plus the rungs, with prefix `refs/remotes/<base>/` or, with no base remote, `refs/heads/`: `<prefix><wsx.baseRef>` alone when the key is set (D-08), else `<prefix>develop`, `<prefix>next` and, with a base remote, `<prefix>HEAD`. A rung name that fails `check_full_ref_name` is left out of the listing and raises that check's error at its rung, which is today's `Error::Gix { what: "read <full>", .. }` from `find_ref`'s first step, so an invalid remote name stays an error in today's order rather than reading as absent. A `wsx.baseRemote` or `wsx.baseRef` error is not raised while the patterns are built: it is raised at its turn in `build`, so error order stays today's (research G6).

What a record means for the model:
- workspace branch: present only as an exact record; a symbolic one is accepted, its `%(objectname)` the tip, as `ref_commit` followed symrefs.
- develop, next, the `wsx.baseRef` rung: an exact record with `%(symref)` set is `IntegrationRefSymbolic { full_ref, target: <%(symref)> }` (D-30); a direct one is the rung, its tip peeled.
- `<base>/HEAD`: a default only when its `%(symref)` starts with the prefix; the branch is the rest, `full_ref` that target and the tip HEAD's own `%(objectname)` (D-34); otherwise it stays in `tried`.
- candidates: prefix plus a non-empty rest without `/`, short names sorted by bytes across both prefixes, less `recorded` (D-17).
Until 04-16 the tips are peeled with `Repo::peel_commit` (gix, by id): the workspace tip mapped to `ManifestUnreadable` as `ref_commit`'s failure was, a rung's tip as `Error::Git`.
