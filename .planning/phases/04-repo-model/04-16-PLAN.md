The batch (research P3; probes F2 to F5, F11 on git 2.56.1):
- `--batch=%(objectname) %(objecttype) %(objectsize) %(objectmode)` prints `<id> <type> <size> <mode>`, then exactly `<size>` bytes and one LF; the mode is empty for a request that is not `<tree-ish>:<path>` (a header ending in a space). A request git cannot answer prints `<request> missing` and LF, exit 0; `ambiguous` cannot occur for full ids. Parse positionally: answer i belongs to request i.
- `<commit>:<path>` modes: `100644`, `100755` (blob), `120000` (symlink, blob type), `040000` (tree), `160000` (gitlink). The default format has no mode and reads a symlink as a blob (G2).
- An absent path, an entry whose blob is gone, and an entry git's sorted lookup misses in an unsorted tree all print `missing`; `<commit>^{tree}` in the same batch returns the root tree, which lists the entry in the last two cases (F3). Raw tree entries are `<ascii mode> SP <name> NUL <raw id>`, a directory's mode written `40000` and the id half the hex length of the tree's id.
- `<id>^{commit}` peels annotated and nested tags; on a blob or tree it prints `missing` (F4). A full hex request is read as that object even when a ref of the same name exists (F11).
- In a `--filter=blob:none` clone, `cat-file --batch` without `--no-lazy-fetch` fetched the blob (F5).
- `missing` is not translated: under `de_DE.UTF-8` and `fr_FR.UTF-8` it printed `missing` while `rev-parse`'s error was translated (probe at planning, G9).

Error order in `build` (research G6), unchanged: `WorkspaceBranchMissing`; `refuse_replace_refs`; base, then push remote; the rung choice (`wsx.baseRef` and chain errors, `IntegrationRefSymbolic`, `NoIntegrationBranch`); the batch child, spawned only now, its failure `Error::Git`; the rung's peel, `Error::Git`; `worktree_dir`; the workspace tip, `ManifestUnreadable`; the manifest (`ManifestMissing`, `ManifestNotABlob`, `ManifestUnreadable`, `ManifestInvalid`).
