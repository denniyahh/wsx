Rule A (`Repo::refuse_linked_worktree_refs(&self) -> Result<(), Error>`, public, reading only what each step names):
1. When `self.git_dir() == self.common_dir()` (a main worktree, a submodule or a bare repo), `Ok(())`:
   there is no separate store, and gix's overlay of a git dir on a common dir exists only when they
   differ. Both paths are canonical (`Repo::from_gix`), so they compare exactly.
2. `stray_private_ref(&self.git_dir().join("refs"))`: `std::fs::read_dir`; `NotFound` is `Ok(None)`;
   any other error, or an entry that fails to read, is `LinkedWorktreeRefsUnreadable { path: <that
   directory>, source }`; otherwise the least entry name, in byte order, whose path
   `is_per_worktree_ref_dir` rejects, as `Some(<that directory>/<name>)`, or `Ok(None)` when every
   entry is exempt.
3. `is_per_worktree_ref_dir(path: &Path) -> bool` is true exactly when the path's file name bytes are
   one of `PER_WORKTREE_REF_DIRS` = `["bisect", "rewritten", "worktree"]` and
   `std::fs::symlink_metadata(path)` says a directory, so a regular file, a symlink or a fifo of one
   of those names is a stray (git reads `refs/bisect` with no trailing component as a shared ref, not
   from there: pi measured).
4. `Some(path)` is `LinkedWorktreeRefsPresent { path }`.
Nothing inside the three namespaces is read; no ref name is parsed.

Rule B (symlinked refs; reads only what each step names):
1. `fn is_symlink_at(path: &Path) -> bool`: `std::fs::symlink_metadata(path)` succeeds and its file
   type is a symlink. Any failure is false: the path is absent or unreachable, and gix's own open or
   walk of that same path then finds nothing or fails with its own error.
2. `fn refuse_symlinked_ref(&self, full: &[u8]) -> Result<(), Error>` (private): for `dir` in
