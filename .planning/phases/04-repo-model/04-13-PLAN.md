The rule (`Repo::refuse_linked_worktree_refs(&self) -> Result<(), Error>`, reading only what each step names):
1. When `self.git_dir() == self.common_dir()` (a main worktree, a submodule or a bare repo), `Ok(())`:
   there is no separate store, and gix's overlay of a git dir on a common dir exists only when they
   differ. Both paths are canonical (`Repo::from_gix`), so they compare exactly.
2. `stray_private_ref(&self.git_dir().join("refs"))`: `std::fs::read_dir`; `NotFound` is `Ok(None)`;
   any other error, or an entry that fails to read, is `LinkedWorktreeRefsUnreadable { path: <that
   directory>, source }`; otherwise the least entry name, in byte order, for which
   `is_per_worktree_ref_dir` is false, as `Some(<that directory>/<name>)`, or `Ok(None)` when every
   entry is `bisect`, `rewritten` or `worktree`.
3. `Some(path)` is `LinkedWorktreeRefsPresent { path }`.
Entry names are matched whole, whatever kind of entry they are; nothing inside the three namespaces
is read; no ref name is parsed.
