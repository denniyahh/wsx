<objective>
Scope and shape of every `wsx.*` read: only this repository's own config file counts (D-01), and a
repeated or empty key this phase reads is an error rather than git's last-one-wins (D-18). And one
setting outside `wsx.*` that changes every ref read: a ref namespace, which gix takes from config or
the environment and git's own reads ignore, is refused when the repository is opened.

Purpose: "configured" decides whether the push guard fails closed. A value leaking in from global
config, or an include read live from a checked-out branch, would change that for an unrelated repo.
A namespace would make the model read other tips and another manifest than git, with no error.
Output: the level filter and its differential tests, `single`'s refusals, `Error::RefsNamespace`.
</objective>

## Flagged cost

Task 3's refusal reaches the whole machine. `gitoxide.core.refsNamespace` in global or system config, or `GIT_NAMESPACE` exported in a shell or a service's environment, makes `Repo::discover` refuse in every repository wsx opens, configured or not. The refusal comes before any model exists, so D-16's "not configured" state, under which the guard exits 0, is never reached: from phase 6, every push through the machine-wide guard in every repository would meet this refusal, unless phase 6 treats a discovery refusal otherwise. 04-10 Task 2 records that choice as a phase 6 obligation. git's own commands are unaffected, and the message names both settings and the command that shows where the key is set.

It could not be narrowed the way 04-11's replace-base check was (refused only while a replace ref exists), because no narrower condition leaves gix reading what git reads. Under a namespace with no refs in it, gix finds no ref at all (measured), so a configured repository would fail with a misleading missing-branch error and a not-configured one would look empty. Clearing the namespace after open with `clear_namespace()` fixed ref reads but left the replacement map gix had loaded through the namespace, which still read a namespaced replacement's bytes where git read the original (measured, see above). Opening with the namespace switched off in `open_gix`, by overriding the key and its `GIT_NAMESPACE` environment override in gix's open options, was not explored; the refusal is the shape the third-review instructions preferred and phase 3 already uses. Neither knob is a git setting: `gitoxide.core.refsNamespace` is gix's own key, and gitnamespaces(7) describes `GIT_NAMESPACE` as rewriting ref names in `git upload-pack` and `git receive-pack`, which serve a fetch or a push; `git show-ref`, `git rev-parse` and `git cat-file` ignored it in the measurements above.
