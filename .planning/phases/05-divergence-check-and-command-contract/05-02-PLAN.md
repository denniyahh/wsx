JSON contract (05-08's schema describes exactly this; later plans add the fields they name):
- Envelope, every object: command (the COMMANDS name), schema_version (its integer).
- check success (exit 0 or 1), keys in this order: command, schema_version, configured (bool), workspace {branch: bytes, tip: string}, integration {branch: bytes, ref: bytes, tip: string}, staleness (05-07), hooks (05-06), problems [{kind: string, path: bytes, detail: string|null}].
- failure (exit 2 to 6): command, schema_version, error {kind: string, message: string, exit_code: integer}. message is the error's Display, which already C-quotes byte values.
- bytes: a JSON string when std::str::from_utf8 succeeds, else the object {"hex": lowercase hex, two digits per byte}. Object ids are hex strings.
- Rendering: compact (no spaces), one trailing newline, nothing else on stdout. Strings escape quote and backslash, use the short escapes for backspace, form feed, newline, carriage return and tab, and \u00XX (lowercase hex) for every other byte below 0x20; every other character is written as its UTF-8.
- Grammar: wsx <name> [--json], --json at most once. A usage error once the first argument is a COMMANDS name, with --json among the later arguments, prints the failure object (kind usage, exit_code 2) on stdout and the usage text on stderr. No argument or an unknown first word: usage text on stderr only, stdout empty, exit 2. The usage lines become "usage: wsx --version" and "usage: wsx <name> [--json]" per entry.
- Sinks: one place decides where a line goes. Diagnostics: stderr. The verdict: stdout without --json, stderr with it. The object: stdout, once, last.
</context>
