Hooks contract:
- pub enum HookStatus { NotSet, NotChecked { value: Vec<u8>, reason: String }, Checked { dir: Vec<u8> } }; Report gains pub hooks: HookStatus.
- Normalising the value: a value beginning with / is NotChecked "it is an absolute path, outside the commits wsx reads"; strip one leading ./, then model::manifest::normalize_path (one trailing / stripped; empty, absolute, dot, dot-dot, empty-component and NUL refused) and a refusal is NotChecked "it is not a relative path inside the repository"; a normalised dir with no MODE_TREE entry of that path in the tip's listing is NotChecked "<dir> is not a directory at the tip of <B>".
- Judging (pure: fn evaluate_hooks(dir, listing, targets) -> Vec<Problem>, targets a map from a symlink's id to its blob): every listed entry strictly below dir that is not MODE_TREE: MODE_EXECUTABLE passes; MODE_SYMLINK passes when it resolves, else detail "a symlink that does not resolve to a tracked executable: <reason>"; any other mode has detail "committed <mode as six octal digits>; commit it with mode 100755". Kind HookNotExecutable (name hook_not_executable); human line "hook not committed executable: P (<detail>)".
- Resolution reasons: "its target <T> is absolute", "its target <T> leaves the tree", "its target <P> is not tracked", "its target <P> is a directory", "its target <P> is committed <mode>", "its target passes through <Q>, which is not a directory", "it is one of more than 40 symlinks in a row" (T, P and Q C-quoted; P and Q are resolved in-tree paths).
- Resolution follows directory links anywhere in the tree (D-03 as amended), so targets holds the blob of every MODE_SYMLINK entry in the listing, inside the hooks directory or not.
- JSON hooks object (before problems): NotSet {path: null, checked: false, reason: "core.hooksPath is not set"}; NotChecked {path: bytes of the value, checked: false, reason}; Checked {path: bytes of dir, checked: true, reason: null}.
- run order: resolve, tree_diff, lookup_paths (05-04), then repo.hooks_path(git)?; when it normalises, repo.list_tree(git, &model.workspace_tip)? and, when the listing holds a symlink, repo.read_blobs(git, &the ids of every MODE_SYMLINK entry in the listing)? in one child.
