<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| container -> host checkout | The container sees the source tree and git directories through bind mounts |
| registry -> local image | The pinned image defines the verification environment |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-09 | Tampering | verification writing to the source checkout | high | mitigate | Worktree and gitdir mounts are `:ro`; build output goes to a named volume via CARGO_TARGET_DIR (read-only probe control) |
| T-01-10 | Tampering | floating or changed base image | high | mitigate | Exact tag in the Dockerfile FROM; digest recorded in the SUMMARY; 01-04's parity check rejects non-exact tags |
| T-01-11 | Tampering | cache aliasing across checkouts (false red or green) | medium | mitigate | Volume names keyed by sha256 of the checkout path |
| T-01-SC | Tampering | tool installs inside the container | high | mitigate | Tools come only through the sha256-pinned scripts/install-tools.sh; no crates installed |
</threat_model>
