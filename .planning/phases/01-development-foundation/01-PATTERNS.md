## Pattern Assignments

### `scripts/check.sh` (utility, batch)

**Analog:** `/home/denniyahh/Github/devflow/scripts/check.sh` (105 lines)

**Header + strictness** (lines 1-9). Keep the "single definition of green" comment; it is why
`check.sh` is the only gate entry point (DEV-01):
```bash
#!/usr/bin/env bash
# The single definition of "is this green?" — used by CI, by the pre-push
# hook, and by scripts/check-in-container.sh. If a check is not in here, it
# is not enforced anywhere; if it is, it is enforced identically everywhere.
#
# Deliberately NOT parameterised by environment. ...
set -euo pipefail
```
Change "pre-push hook" in the comment: wsx Phase 1 adds no pre-push hook (RESEARCH anti-pattern).

**Usage block** (lines 11-27): heredoc to stderr, `exit 2`. Drop the `build` target; `deps` line
names `scripts/install-tools.sh`, not `install-dep-tools.sh`.

**Per-target functions** (lines 31-41, 43-61, 68-84):
```bash
run_fmt() {
    echo "==> cargo fmt --check"
    cargo fmt --check
}

run_clippy() {
    # --all-targets so test and bench code is linted too; ...
    echo "==> cargo clippy --workspace --all-targets -- -D warnings"
    cargo clippy --workspace --all-targets -- -D warnings
}
```
- `run_test` (43-61): keep the `--no-fail-fast` rationale comment (44-48). Drop the insta
  `env -u INSTA_FORCE_UPDATE INSTA_UPDATE=no` wrapper (wsx has no insta). Replace `cargo test` with
  `cargo nextest run --locked --workspace --no-fail-fast --no-tests=fail "$@"`. `--no-tests=fail`
  must precede `"$@"` (RESEARCH Pattern 1, Pitfall 4).
- `run_deps` (68-84): keep the "Not part of `all`" and "missing tool is a hard error, never a
  skip" comments (69-72). Drop `cargo-machete` (not a Phase 1 requirement). Run
  `cargo deny --locked check`. RESEARCH recommends `scripts/install-tools.sh verify cargo-deny`
  first, so a brew upgrade cannot silently unpin the scanner on the host.

**Missing-tool check:** devflow only checks tools in `run_deps` (73-79):
```bash
    local tool
    for tool in cargo-deny cargo-machete; do
        if ! command -v "$tool" >/dev/null 2>&1; then
            echo "error: $tool is not installed; run scripts/install-dep-tools.sh" >&2
            exit 1
        fi
    done
```
Generalise this into a `require_tool <binary> <how-to-get-it>` helper called at the top of every
`run_*` (RESEARCH Pattern 1). fmt needs `cargo` + `cargo-fmt`; clippy needs `cargo` +
`cargo-clippy`; test needs `cargo` + `cargo-nextest`; deps needs `cargo-deny`. The error must name
the tool (control C1).

**Dispatch** (lines 86-105):
```bash
case "$TARGET" in
    all)
        # Cheapest first: fail on formatting before paying for a compile.
        run_fmt
        run_clippy
        run_test
        ;;
    fmt) run_fmt ;;
    ...
    -h | --help | help) usage ;;
    *)
        echo "error: unknown target '$TARGET'" >&2
        usage
        ;;
esac

echo "==> check.sh: $TARGET OK"
```
Changes:
- `TARGET="${1:-all}"; shift || true`, so `test` can pass extra args (needed for control C2).
- Other targets reject extra args.
- Resolve the repo root from the script's own location
  (`cd "$(dirname "${BASH_SOURCE[0]}")/.."`), not from git.

## Shared Patterns

### Bash script skeleton
**Source:** devflow `scripts/check.sh:1-9`, `scripts/check-in-container.sh:1-15`, and wsx
`scripts/workspace/phase-worktree.sh:1-17`. Both repos use the same style.
**Apply to:** all five new `scripts/*.sh`
- `#!/usr/bin/env bash`
- a header comment that explains WHY the script exists and the failure it prevents
- `set -euo pipefail`
- errors go to stderr as `echo "error: ..." >&2`
- exit 1 for a failure; exit 2 for usage, as in devflow `check.sh:26` and wsx
  `phase-worktree.sh:23,30`
- progress lines are prefixed `==> `
- multi-line errors use `cat >&2 <<'EOF'`

Lint every script with `shellcheck` + `bash -n`. shellcheck exists on the host only, not in the
image.

### Fail closed, never skip
**Source:** devflow `scripts/check.sh:69-72` ("A missing tool is a hard error here, never a skip —
a skipped check prints nothing a log reader can tell apart from a passing one") and
`assert-image-parity.sh:26-29` (empty extraction = error).
**Apply to:** `check.sh` (require_tool), `install-tools.sh verify`, `assert-image-parity.sh`
(zero workflow images = error), `check-in-container.sh` (empty FROM = error).

### Single pin site + parity enforcement
**Source:** devflow `install-dep-tools.sh:4` ("single place their versions are pinned"),
`check-in-container.sh:34-35` ("Single source of truth for the image tag"), `ci.yml:26-29`.
**Apply to:**
- tool versions in `install-tools.sh` only
- image tag in `.devcontainer/Dockerfile` only, with the workflow copies enforced by
  `assert-image-parity.sh`
- rustc in `rust-toolchain.toml` only

### Container job boilerplate
**Source:** devflow `ci.yml:41-60` (container + safe.directory step) and `ci.yml:100-110`
(`shell: bash` reason).
**Apply to:** every job in `ci.yml` and `deny.yml`, plus the SHA-pinned checkout with
`persist-credentials: false` and `permissions: contents: read`.

### Ruleset-trap comment
**Source:** devflow `ci.yml:9-19` and `.github/workflows/devcontainer.yml:1-17`. Required-context
names must equal job `name:`; check `rules/branches/<b>`, not `branches/<b>/protection`.
**Apply to:** `ci.yml` header (only `ci.yml` jobs are required; `deny.yml` is advisory).
