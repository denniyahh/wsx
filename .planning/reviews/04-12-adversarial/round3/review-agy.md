### Redundant sub-mechanism: `PackedRefsDuplicate` on non-replace refs
- **Mechanism**: In [04-13-PLAN.md#L134](file:///tmp/claude-1000/-var-home-denniyahh-Github-wsx/21a6fcdb-a844-40bf-85a9-2914cac8c18f/scratchpad/xr3/snapshot/.planning/phases/04-repo-model/04-13-PLAN.md#L134) and [04-13-PLAN.md#L261](file:///tmp/claude-1000/-var-home-denniyahh-Github-wsx/21a6fcdb-a844-40bf-85a9-2914cac8c18f/scratchpad/xr3/snapshot/.planning/phases/04-repo-model/04-13-PLAN.md#L261), `refuse_misordered_packed_refs` sorts all records in `packed-refs` and refuses any duplicate record across the entire file as `PackedRefsDuplicate { path, name }`.
- **Why it can be cut**:
  1. For replace refs (`refs/replace/*`), `gix`'s iterator lists both records, and 04-11's `ReplacementRefDuplicate` already refuses duplicate replace refs. 04-12 Task 3 explicitly reworded `ReplacementRefDuplicate` ([04-12-PLAN.md#L296](file:///tmp/claude-1000/-var-home-denniyahh-Github-wsx/21a6fcdb-a844-40bf-85a9-2914cac8c18f/scratchpad/xr3/snapshot/.planning/phases/04-repo-model/04-12-PLAN.md#L296)) to cover two records of one name in `packed-refs`.
  2. For non-replace refs (e.g. duplicate `refs/heads/main` records), measured on `git 2.56.1`:
     ```bash
     RECORD=$(tail -n 1 .git/packed-refs)
     echo "$RECORD" >> .git/packed-refs
     git rev-parse refs/heads/main
     # Output: bbbb1c88972ee1426bcdef8a81f546012ce3a085 (exit 0)
     git cat-file blob HEAD:file.txt
     # Output: hello (exit 0)
     ```
     `git` does not abort or diverge on duplicate non-replace records; both git and gix resolve the branch tip to the same commit and read the exact same manifest bytes.
- **Verdict**: Cutting the duplicate check from `refuse_misordered_packed_refs` (or restricting it to names starting with `git_base`) leaves all replace-ref duplicates guarded by `ReplacementRefDuplicate` without reopening any measured divergence. Keeping it remains an acceptable over-refusal under D-22, but represents the only surplus check.
